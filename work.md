    <p class="sample-note">The examples below are synthetic illustrations of the kind of work the practice takes. They are not client case studies, and they have not been delivered for a named organization.</p>

    <div class="stack">
      <article class="page-card">
        <p class="kicker">Sample example</p>
        <h2>Finance KPI Trust Reset</h2>
        <p><strong>Theme:</strong> Governed semantic layer</p>
        <p><strong>Problem.</strong> Finance and operations reconcile different versions of the same metrics.</p>
        <p><strong>Approach.</strong> Conformed dimensions, a governed semantic model, and a KPI catalog with owners.</p>
        <p><strong>Sample demonstration.</strong> A synthetic SQL or Fabric source, a Gold model, and a Power BI executive page.</p>
        <p><strong>Outcome target.</strong> One authoritative definition set, controlled releases, and a faster decision review.</p>
      </article>

      <article class="page-card">
        <p class="kicker">Sample example</p>
        <h2>Fabric Modernization</h2>
        <p><strong>Theme:</strong> Medallion architecture</p>
        <p><strong>Problem.</strong> Reporting depends on fragmented extracts, with no durable path from raw data to consumption.</p>
        <p><strong>Approach.</strong> A clear medallion flow — raw landing, conformed transforms, and gold consumption — on Fabric / OneLake, surfaced through a semantic layer and Power BI.</p>
        <p><strong>Sample demonstration.</strong> Public or synthetic data, not client data, moving through that path.</p>
        <p><strong>Outcome target.</strong> A reusable pattern leaders can extend, rather than a one-off dataset.</p>
      </article>

      <article class="page-card">
        <p class="kicker">Sample example</p>
        <h2>Power BI Governance</h2>
        <p><strong>Theme:</strong> Lifecycle and security</p>
        <p><strong>Problem.</strong> Workspaces, access, and releases grew organically. Changes go straight to production, and ownership is unclear.</p>
        <p><strong>Approach.</strong> Dev / Test / Prod, group-based access, RLS where it is warranted, endorsement, and a defined release path.</p>
        <p><strong>Sample demonstration.</strong> A governance pack and a Git or deployment-pipeline example built on synthetic assets.</p>
        <p><strong>Outcome target.</strong> Changes move through an explicit lifecycle, with a named owner for models, refresh, and security.</p>
      </article>
    </div>
  </div>
</section>
